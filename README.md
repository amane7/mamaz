# MAMOA（マモア）

> 産後の不安に、温もりが届く。助産師の手のぬくもりを、24時間そばに。

MAMOAは、母親・家族、助産師・助産院、自治体をつなぐ産後ケアWebアプリの高機能プロトタイプです。単なる「業務効率化」ではなく、予約・問診・通知・カルテ・利用実績の事務をMAMOAへ任せ、助産師が本来のケアに集中できる状態を目指しています。

## 3つの差別化

1. **AI × 助産師のハイブリッド** — 24時間のAI健康相談、回答信頼度・根拠表示、危険時・低信頼度時のhuman-in-the-loop
2. **母乳ケア専門性** — 授乳・搾乳記録、乳房観察、母乳ケア問診、SOAP、授乳姿勢ガイド
3. **自治体連携** — 産後ケア利用券、利用回数管理、実績報告、PMH・電子母子手帳・FHIRの将来構想

## LINE業務アプリ化

設計原則は **「Chatless by default, Human when it matters.」** です。LINE MINI App／LIFFを想定し、標準予約と事務手続きはボタン中心で完了し、健康上の赤旗や制度・移動・枠の例外だけを理由付きで人へ引き継ぎます。

- LINE LoginとLINE user IDによる本人識別UI
- ホーム、予約、予約確認・変更、当日案内、相談の5主要導線
- 目的起点の6ステップ予約、差分問診、10分間の仮押さえ
- `DRAFT`から`NO_SHOW`までの予約ワークフロー状態
- 規約・キャンセル規定の版と予約時スナップショット
- 専門判断、予約例外、事前確認、顧客回答待ち、管理者作業待ちの分離キュー
- `webhookEventId`による冪等性、送達状態、再送、LINE月間送信枠の監視
- URLディープリンク（例：`?mode=mama&action=book`）とPC代替導線

## v2.1：スキル × OK／NG時間の自動予約

v2.1では、シフトの有無だけでなく、助産師本人が登録する可用性を予約判定の正本にしました。予約エンジンは **「必要スキル × OK／NG時間 × 移動・バッファ・負荷上限」** を照合し、条件をすべて満たす助産師がいる時間だけを家族へ提示します。

判定順序と安全ルール：

1. 必要資格・必要スキル・対応サービスを完全一致で確認
2. 予約時間と前後バッファ全体が明示的なOK時間に含まれることを確認
3. NG時間と1分でも重なる候補を除外（NGが常に優先）
4. 確定予約・有効な仮押さえ・利用中予約とのスタッフ別競合を確認
5. 施設、訪問地域、前後移動時間、予約間バッファを確認
6. 1日対応上限・連続対応上限を確認
7. 複数候補を負荷平準化、移動効率、継続性でランキング

プライバシー原則：

- OK未登録時間は原則予約不可
- NG理由は任意入力で、本人限定の非公開情報
- 管理者にはOK／NGの可否だけを投影し、理由をデータから除去
- 家族には内部の候補者情報や除外理由を出さず、受付可否だけを表示
- 管理者の代理入力・補正は理由コード付きの追記専用監査ログへ記録
- 仮押さえ、予約確定、日時変更の各書き込み時に予約エンジンを再実行

## v2.0からv2.1への主な差分

| 項目 | v2.0 | v2.1 |
|---|---|---|
| スタッフ可用性 | 施設シフト・定員中心 | 本人入力のOK／NG時間を正本化 |
| 予約可否 | 施設時間と重複の簡易判定 | スキル、OK／NG、移動、バッファ、負荷を統合判定 |
| NGの扱い | 明示規則なし | OKより優先し、1分の重複でも除外 |
| 未登録時間 | 施設枠に依存 | 明示OKがなければ予約不可 |
| 候補選定 | 固定・簡易割当 | 負荷、移動、継続性でランキング |
| プライバシー | 一般的な権限表示 | NG理由の本人限定化と管理者向け投影 |
| 書込時安全性 | 画面側の重複確認 | 仮押さえ・確定・日時変更時にも再判定 |

## AI安全設計

現在のデモは助産師監修知見を模したルールベースRAGです。AIは診断せず、健康相談として情報整理と受診目安の確認を支援します。

エスカレーション条件：

- 自傷念慮に関する表現
- 大量出血の可能性
- 38℃以上の高熱、乳房症状を伴う発熱
- 140/90mmHg以上を示唆する血圧相談
- EPDS 9点以上、または自傷項目1点以上
- AI回答信頼度が基準未満
- RPM異常値（血圧、体温、心拍）

> MAMOAは医療サービスではなく、医師の診断に代わるものではありません。体調に不安がある場合は医療機関にご相談ください。

## v2.1 KPI・受入基準

主要KPI：

- スキル不一致またはNG時間への予約割当：**0件**
- 今後14日分のOK時間登録率
- セルフサービス完結率
- 手動調整率、NG競合数、移動・バッファ起因の除外数
- 助産師の事務時間削減とケア時間への再配分

MVP受入基準：

- 助産師本人がスマートフォンからOK時間・NG時間を登録、変更、削除できる
- 予約時間と前後バッファ全体を含むOK時間だけが候補になる
- NG時間がOK時間より優先され、1分でも重なる候補は除外される
- OK未登録時間は予約不可になる
- 必要スキルをすべて満たす助産師だけが候補になる
- 確定予約、有効な仮押さえ、移動、バッファ、日次・連続上限を判定できる
- NG理由や私的予定を管理者・家族へ開示しない
- 管理者代理入力が監査ログへ残る

## リスクと対策

| リスク | 対策 |
|---|---|
| NG理由から私生活が推測される | 理由入力を任意にし、本人限定で保持。管理者投影時に理由フィールドを除去 |
| 同時申込による二重予約 | 本番ではDBトランザクション、排他制御、冪等キー、期限付き仮押さえを使用 |
| 移動時間の過小評価 | 現在はヒューリスティック。本番では住所・経路APIと交通条件を使用 |
| 繰り返し予定の誤展開 | 曜日・開始日を基準に展開し、本番では例外日上書きとタイムゾーンを厳密管理 |
| 助産師の登録負担 | 平日一括登録、毎週パターン、終日NGを提供。前週コピーは次段階 |

## MVP実装優先順位

1. **P0**：本人OK／NG入力、NG優先、OK未登録不可、必要スキル一致、予約競合防止
2. **P0**：NG理由の非公開化、管理者代理入力、監査ログ
3. **P0**：仮押さえ・予約確定・日時変更時のサーバー側再判定
4. **P1**：移動時間、前後バッファ、日次・連続上限、候補ランキング
5. **P1**：例外日上書き、前週コピー、日／週／月カレンダー
6. **P2**：実経路API、待機リスト、代替時間提案、高度な負荷最適化
